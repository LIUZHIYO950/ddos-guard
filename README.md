## 1. 这个项目是干什么的

LADS 是一套运行在 **OpenResty（Nginx + Lua）** 上的防护程序。它不依赖任何云厂商的安全产品，也不收一分钱，只要你的服务器能装 OpenResty，就能一键部署。

它主要解决三类问题：

| 你要防的东西 | 通俗解释 |
|---|---|
| DDoS / CC 攻击 | 有人用大量假流量把你的服务器"打趴下"，别人访问不了你的网站 |
| 恶意扫描 / 爆破 | 有人用脚本不断试探你的密码、端口，想黑进服务器 |
| 爬虫 / 脚本刷量 | 机器脚本反复请求你的页面，占满带宽和 CPU |

装上 LADS 之后，这些流量会被挡在"应用层入口"，真正常用的用户（浏览器访问者）几乎无感。

## 2. 它能防御哪些攻击

| 攻击类型 | 攻击手法 | LADS 怎么防 |
|---|---|---|
| **SYN Flood（SYN 洪水）** | 发大量只握手不建立的半连接，占满连接表 | 调整内核参数 + 防火墙限制半连接，见 `conf/nginx.conf.tpl` |
| **UDP / ICMP 洪水** | 大量垃圾包轰炸端口 | 防火墙丢弃异常包，L4 连接表限流 |
| **HTTP 洪水（应用层 DDoS）** | 高频请求页面/接口，耗尽 CPU | 全局熔断：窗口内请求数超阈值 → 拒绝无签名请求 30 秒 |
| **慢速攻击（Slowloris 等）** | 慢慢发请求头，长时间占住连接不关闭 | 传输层超时 + 连接数限制，超时自动断开 |
| **单 IP 攻击 / 爆破** | 同一个 IP 高频访问、试密码 | 单 IP 限流，超限直接拒绝并临时拉黑 |
| **脚本爬虫 / 无头流量** | 无浏览器特征、不带 Cookie 的机器请求 | JS 挑战页（Proof-of-Work）识别真人浏览器，通过后发放签名 Cookie |
| **高频遍历 / CC** | 针对某个 URL 集中打击 | 精确到 URL 的计数 + 熔断 |

> 诚实说明：LADS 的强项是**网络层 / 传输层 / 应用层流量型攻击**（DDoS、CC、爆破、爬虫）。对于**带宽型大流量攻击**（比如几十 Gbps 直接把带宽塞满），单机防御无能为力，需要云厂商的高防或 CDN 配合。SQL 注入、XSS 等**代码层漏洞**请配合开发规范与 WAF 使用。

## 3. 实现逻辑（小白版）

所有进入服务器的请求，会先经过 LADS 的"安检门"，按下面的顺序检查：

```
用户请求
  │
  ├─ 第 1 步：查黑名单 ── 是 → 直接拒绝（返回 YISIDDOS 提示）
  │
  ├─ 第 2 步：带合法签名 Cookie？ ── 是 → 直接放行
  │
  ├─ 第 3 步：单 IP 限流检查 ── 超限 → 拒绝 + 临时拉黑
  │
  ├─ 第 4 步：全局熔断检查（看整台服务器的流量是不是异常）
  │     触发熔断 → 所有"无签名"请求拒绝 30 秒
  │
  └─ 第 5 步：还没验证过 → 返回 JS 挑战页
         浏览器自动算出结果 → 拿到签名 Cookie → 下次直接放行
```

**关键机制，用大白话讲：**

1. **签名 Cookie（HMAC）**：服务器用一把只有自己知道的密钥给浏览器发"通行证"（HMAC 签名 Cookie）。拿到通行证的人下次直接放行，没拿到的一律当可疑对象。
2. **全局熔断**：LADS 盯着整台服务器的请求频率，分 5 档（0.5 秒 150 次 / 1 秒 200 次 / 1.5 秒 250 次 / 2 秒 300 次 / 3 秒 1000 次）。任一档被触发，就说明"来者不善"，熔断 30 秒，期间只放行带签名 Cookie 的真用户。
3. **无状态验证**：LADS 不存会话、不存用户表，验证全凭 Cookie 里的签名，省内存、重启不丢状态。
4. **JS 挑战（Proof-of-Work）**：不是直接拦浏览器，而是让浏览器算一道小谜题（几秒内算完），真人浏览器秒过，脚本工具算不出来就被挡在外面。

这套逻辑全部用 Lua 写在 OpenResty 里，和你的网站业务代码完全解耦，部署/卸载都不影响原程序。

## 4. 部署方法一：从源代码部署

适合：想从 GitHub 拉最新源码、跟着仓库走的用户。

### 准备阶段（先确认 3 件事）

- [ ] 一台服务器（Linux 系统，CentOS / Ubuntu / Debian / 腾讯OS 均可），**能连外网**
- [ ] 服务器有 **root 权限**（或 sudo 权限）
- [ ] 服务器已安装 **Git**（没装就执行：CentOS 用 `yum install -y git`，Ubuntu 用 `apt install -y git`）

### 第 1 步：克隆源码

```bash
git clone https://github.com/liuzhiyo950/ddos-guard.git
cd ddos-guard
```

> 如果没装 Git 或克隆太慢，可以直接用下面的"发布包部署"方式，效果完全一样。

### 第 2 步：一键部署

```bash
sudo bash deploy.sh 你的后端地址 你的端口
```

解释一下两个参数：

| 参数 | 说明 | 例子 |
|---|---|---|
| 后端地址 | 你真正的网站/程序地址（LADS 挡在前面，把请求转发给它） | `127.0.0.1` 或 `你的服务器IP` |
| 端口 | 你真正的网站/程序监听的端口 | `8080`、`3000` 等 |

例子：你的网站跑在本机 8080 端口，对外用 80 端口：

```bash
sudo bash deploy.sh 127.0.0.1 8080
```

### 第 3 步：等待自动安装

脚本会自动帮你：
1. 安装 OpenResty（如果没装）
2. 生成 LADS 的 Nginx 配置
3. 拷贝 Lua 防护模块和挑战页
4. 启动并设置开机自启

看到 `部署完成` 字样就成功了。

### 第 4 步：让防火墙放行对外端口

```bash
# 以对外端口 80 为例
sudo firewall-cmd --permanent --add-port=80/tcp && sudo firewall-cmd --reload
# 如果没装 firewall-cmd，改用 iptables：
# sudo iptables -A INPUT -p tcp --dport 80 -j ACCEPT
```

> 默认对外端口：如果没指定，脚本默认用 **80 端口** 对外服务。

### 第 5 步：验证

浏览器访问 `http://你的服务器IP/`：
- 第一次访问会看到一个短暂的"安全验证"页（几秒），之后自动跳转到你的网站 —— 说明防护生效
- 直接看到你的网站内容 —— 也正常，说明你的浏览器已拿到签名 Cookie

部署结束。以后想更新代码，进目录执行 `git pull` 后再跑一次 `deploy.sh` 即可。

## 5. 部署方法二：从发布包部署

适合：不想装 Git、不想拉源码，只想"下载一个压缩包解压就能用"的用户。

### 准备阶段

- [ ] 一台 Linux 服务器，有 root / sudo 权限
- [ ] 把发布包 `lads-github-publish.tar.gz` 上传或下载到服务器（放哪个目录都行，比如 `/root`）

### 第 1 步：解压

```bash
tar -xzf lads-github-publish.tar.gz
cd lads-publish
```

### 第 2 步：一键部署

和源码方式完全一样：

```bash
sudo bash deploy.sh 你的后端地址 你的端口
```

例如：

```bash
sudo bash deploy.sh 127.0.0.1 8080
```

### 第 3 步：放行端口并验证

```bash
sudo firewall-cmd --permanent --add-port=80/tcp && sudo firewall-cmd --reload
```

然后浏览器访问 `http://你的服务器IP/`，能正常看到你的网站即部署成功。

> 源码包和发布包的内容是同一套代码，只是获取方式不同。你以后想升级，重新下载新版本发布包，解压覆盖后重跑一次 `deploy.sh` 即可，配置会保留。

## 6. 部署完成后怎么验证

| 验证项 | 方法 | 预期结果 |
|---|---|---|
| 防护是否生效 | 浏览器访问站点，首次会短暂出现验证页 | 几秒后跳转到你的网站 |
| 单 IP 限流 | 用命令快速连打 20 次 `curl -s http://你的IP/` | 出现 `YISIDDOS` 提示或连接被拒 |
| 熔断是否触发 | 写脚本 1 秒内发 300 个请求 | 后续请求被拒绝 30 秒 |
| 服务状态 | `systemctl status openresty` | 显示 active (running) |
| 卸载 | `sudo bash deploy.sh --uninstall`（若支持）或删除配置重载 | 恢复原状 |

## 7. 参数说明（进阶）

所有防护阈值都在 `conf/nginx.conf.tpl` 里，改完执行 `sudo bash deploy.sh 后端地址 端口` 重新渲染生效：

| 参数 | 默认值 | 含义 |
|---|---|---|
| 单 IP 窗口大小 | 5 秒 | 统计窗口 |
| 单 IP 窗口上限 | 50 次 | 单个 IP 每窗口最多请求数 |
| 熔断第 1 档 | 0.5s 内 150 次 | 全局频率超过即熔断 |
| 熔断第 2 档 | 1s 内 200 次 | 同上 |
| 熔断第 3 档 | 1.5s 内 250 次 | 同上 |
| 熔断第 4 档 | 2s 内 300 次 | 同上 |
| 熔断第 5 档 | 3s 内 1000 次 | 同上 |
| 熔断时间 | 30 秒 | 触发后拒绝无签名请求的时长 |
| 签名 Cookie 有效期 | 24 小时 | 真用户通行证有效期 |

业务高峰期如果担心误伤，可以适当调大阈值；遭遇攻击时调小，防护更激进。

## 8. 常见问题 FAQ

**Q1：我没有域名，只有 IP，能用吗？**
能。直接用 IP 访问即可，LADS 不依赖域名。

**Q2：我的网站是 HTTPS（443 端口）的，怎么办？**
LADS 支持在 Nginx 层配置 SSL。部署后按 OpenResty 标准方式在 `conf/nginx.conf.tpl` 中加证书配置，再用 `deploy.sh` 重新渲染。

**Q3：部署后我的网站打不开了？**
先确认后端地址和端口参数写对了；再确认对外端口已放行；最后看日志：`sudo tail -f /var/log/openresty/error.log`。

**Q4：误伤正常用户怎么办？**
正常浏览器能自动通过 JS 挑战并拿到 Cookie，一般不会误伤。如果批量用户被挡，说明阈值太紧，调大第 7 节里的参数即可。

**Q5：LADS 和我现有的 Nginx 冲突吗？**
LADS 用的是 OpenResty（内置增强版 Nginx），建议独立安装使用；如果服务器已有 Nginx 占用了 80 端口，请先停掉它或让 LADS 用其他端口对外。

**Q6：能防住所有攻击吗？**
不能，任何防御都不能 100%。LADS 能防住绝大多数**流量型**攻击；超大带宽型攻击（几十 Gbps 以上）需要云高防 / CDN 配合。
